# CLPR 1.1 完整操作指南

CLPR 用于从已知正常的本地快照找回 Codex 的项目列表和聊天归属。它不负责登录、切换账号或授予跨账号云端权限。

## 一、第一次打开

1. 获取 Windows x64 发行包 `CLPR-1.1.0-Windows-x64.zip`。
2. 将整个压缩包解压到你自己的文件夹。双击其中的 `Clpr.Desktop.exe`，不需要安装 .NET 或以管理员身份运行。
3. 首页为「状态与备份」。默认目录为当前 Windows 用户的 `%USERPROFILE%\.codex`，不是开发演示目录。
4. 如果你曾迁移 Codex 数据，点击「选择目录」，选择包含 `.codex-global-state.json` 的数据文件夹；不要选择某个项目的源码文件夹，也不要选择单独的 JSON 文件。
5. 点击「重新扫描」，查看当前项目数、聊天归属数、可恢复快照数量与 Codex 运行状态。

扫描只读取状态。看到“Codex 正在运行”时仍可扫描、保存快照和生成预览；实际写回与回滚要求 Codex 完全退出。

## 二、项目正常时：保存切号前快照

1. 先打开 Codex，确认左侧项目列表、项目分组和历史聊天归属符合预期。
2. 在本工具左侧选择「状态与备份」。
3. 确认数据目录正确，点击「保存当前快照」。
4. 出现“快照已保存”和实际项目/归属数量后，备份完成。
5. 现在可以正常切换账号。**保存快照不会执行恢复，也不需要立即点击恢复。**

保存的快照会自动加入「恢复项目」列表，标注为「已保存快照」，不需要记住文件路径或再次手动导入。之后新增或调整项目时，可以再保存一份最新快照；旧快照保留，多份以保存时间区分。

清理旧快照时，在「恢复项目」选中一条「已保存快照」，点击「删除所选快照」并确认。该快照会移到 Windows 回收站。按钮适用于 CLPR 保存的快照。

空列表或未通过结构校验的状态不会作为正常快照保存。如果项目已经消失，应先查找历史正常备份，而不是把空状态当作恢复来源。

## 三、正常切换到另一个账户

1. 按你原来的正常登录流程切换 Codex 账户。本工具不替你切号，也不复制登录文件。
2. 登录完成后，查看项目列表是否仍正常。
3. **项目正常：到这里就结束，不需要恢复。**
4. 项目消失或聊天分组缺失时，再按下节操作。

如果当前列表仍有部分项目，但你希望恢复到某份快照，可按下节生成覆盖预览。确认后会以所选快照的项目和归属为准。

## 四、选择快照并生成预览

1. 确认已经登录到你希望使用的账户，然后**完全退出 Codex**。不要只关掉窗口却保留后台进程，也不要在修复过程中继续切号。
2. 单独打开 CLPR。修复工具可以保持运行，退出的是 Codex。
3. 左侧点击「恢复项目」。进入时会重新扫描；也可以点击列表右上角「刷新」。
4. 选择切号前保存的「已保存快照」。核对项目数量、聊天归属数量和保存时间，优先使用你确认正常且合适的版本。
5. 如果没有已保存快照，也可以选择列表中的「Codex 自动备份」「历史临时快照」或「旧版正常备份」，但需自己核对其适用性。最新或数量最多不代表一定正确。
6. 其他位置的正常 JSON/bak/tmp 文件，可以通过「导入快照」加入列表。
7. 点击「生成恢复预览」。预览本身不会修改 Codex 状态。

当前正在修复的状态文件不会混在恢复来源列表里，避免误把目标文件当成备份。列表中的项目数与归属数均从当次读取的内容动态计算。

### 如何看预览

- **来源**：所选快照中的项目数与聊天归属数。
- **当前**：目标数据目录当前的项目数与聊天归属数。
- **覆盖差异**：当前已有数据时，分别显示项目和聊天归属的新增、替换和移除数量。
- **检查通过**：目标为空时可点「恢复项目」，目标非空时可点「覆盖当前项目」。
- **暂不恢复**：阅读预览区给出的具体原因，按钮保持禁用。

「查看文件路径与校验详情」可展开查看来源、目标、SHA-256 和将修改的字段。「导出详情」可保存计划用于本地核对；导出内容含本地路径，请不要直接公开上传。

## 五、预览通过后：直接恢复

1. 确认所选快照、目录与预览数量符合你的预期。
2. 确认 Codex 已完全退出。
3. 目标为空时，点击亮起的「恢复项目」。目标已有项目时，点击「覆盖当前项目」，在确认框核对覆盖前后的数量和移除数量，再点「确定」。
4. 工具会自动再次检查进程和源/目标哈希，备份操作前文件，生成候选状态，原子写回并执行写后校验。
5. 等待出现恢复完成提示。
6. 重新打开 Codex，保持使用你刚才登录的账户，检查项目能否显示、展开，以及历史聊天归属是否正确。

覆盖时仅存在于当前状态中的项目和聊天归属会从列表移除。对应的失效置顶、侧栏引用，以及与新归属冲突的无项目标记会一并清理。聊天记录和项目文件仍在原位置。需要撤销时，可在「操作记录」回滚到覆盖前的备份。

文件级恢复完成不等于应用界面已经验证。如果 Codex 仍不显示项目或再次将列表清空，请记录现象并重新扫描，不要连续反复点击恢复。新版 Codex 的内部结构或账号可见性规则可能需要另行检查。

## 六、如果需要撤销：回滚指定操作

1. 完全退出 Codex。
2. 在 CLPR 左侧点击「操作记录」。
3. 按时间和恢复数量选择需要撤销的那一次操作。
4. 状态为「可回滚」时，点击「回滚选中操作」，核对确认框中的时间后确认。
5. 等待回滚完成。回到「状态与备份」重新扫描，再打开 Codex 检查。

操作记录展示本工具执行过的恢复，不是已保存快照的列表。仅保存快照、不执行恢复时，没有操作记录是正常的。

「状态已变化」表示当前文件已不再等于那次恢复后的内容，为避免覆盖之后的变化，不允许自动回滚。「已回滚」表示已撤销；「未完成 / 待核对」需要保留备份并人工检查。其他位置的操作记录可通过「导入操作记录」选择 `manifest.json`。

## 七、常见情况

| 情况 | 如何处理 |
| --- | --- |
| 恢复按钮是灰色 | 先选择来源并生成预览；如果预览未通过，阅读预览区原因。 |
| 预览通过后按钮又灰了 | 选择、目录或状态文件发生变化，旧计划已失效，重新预览。 |
| 提示 Codex 仍在运行 | 完全退出 Codex 及相关后台进程，再点击恢复；工具不会强制结束进程。 |
| 当前已有部分项目 | 选择完整快照并预览差异，再点击「覆盖当前项目」确认。 |
| 当前项目数据已与快照一致 | 所选快照与当前项目数据相同。可以检查是否选中了预期的快照。 |
| 提示文件已变化或哈希不一致 | 重新扫描并生成新预览，不继续使用旧计划。 |
| 列表没有可用快照 | 检查目录是否正确；有其他正常备份时通过「导入快照」选择。没有可靠来源时不能凭空还原项目归属。 |
| 某个历史快照显示“不支持恢复” | 内容可能损坏、结构不支持或引用不完整，选择另一份经过校验的正常来源。 |
| 保存成功后不知道下一步 | 可以直接正常切号；只有切号后项目消失才需要恢复。 |
| 换账户后项目仍正常 | 无需执行恢复，继续正常使用。 |
| 操作记录为空 | 尚未用本工具执行过恢复是正常情况；保存快照不会产生恢复记录。 |

## 八、数据位置和隐私

- 正常快照：`%LOCALAPPDATA%\CLPR\snapshots`。
- 操作备份和回滚记录：`%LOCALAPPDATA%\CLPR\operations`。
- 旧版 CLPR 保存的快照和记录可以继续使用，不需要重新生成。

这些是运行后在你自己电脑上产生的数据，不随公开发行包提供。备份可能含真实项目路径、聊天相关数据库等私密信息；不要将整个备份目录、原始状态或导出计划上传到公开 Issue。软件无需联网，不上传快照或遥测，不读取 `auth.json`。

## 九、范围与校验

本工具非 OpenAI 官方工具，不负责账号登录、账号切换或云端项目授权。SQLite 只备份，不验证数据库 ID。当前仅支持已适配的 V1 内部 JSON 结构，Codex 更新后可能需要新适配器。

发行包附 ZIP 的 SHA-256，解压包内也有两个可执行文件的校验和。43 项核心测试使用合成临时目录。
